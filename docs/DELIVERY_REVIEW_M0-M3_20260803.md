# 开发组作品对抗性复核综述（M0-M3）

复核日期：2026-08-03  
复核范围：版本基线、SCT 地形链路、展示站登录贯通、项目级 iServer 数据中心

## 已形成的可核验证据

1. `/api/system/status`、README、报告页统一返回版本 `4.2.0`，默认数据根目录不再指向个人绝对路径。
2. 三维接口增加地形诊断契约；前端用 `TerrainController` 显式替换 `viewer.terrainProvider`，并把 SCT、Cesium 在线地形和椭球降级状态写入界面。
3. 展示站入口通过白名单 `next` 进入真实登录页，登录后只能跳转到真实控制台路径，外部 URL 会被拒绝。
4. 数据中心所有查询先校验项目所有权，再按 `project_id + current_user.id` 查询资产；删除先请求 iServer，成功后才软删除本地记录。
5. 已有 SQLite 数据库通过幂等 `scripts/migrate_v42.py` 增加 `project_id` 列和索引，不要求删除数据库重建。

## 当前不能在代码审查中替代的现场证据

- iServer 真实服务目录、Realspace 场景、SCT 数据和远端删除行为仍需在比赛机上录制截图/录像。
- 三维地形开关的像素差异与相机拾取高程需要安装 SuperMap3D 后用浏览器自动化复核。
- 评估主链路的数据真实性、洛南案例数据台账和 AI 助手属于 M4-M5，不应在本轮演示中提前宣称完成。

## 结论

M0-M3 的代码闭环和权限边界已具备可审查证据，剩余风险集中在外部 iServer/SuperMap3D 运行时和比赛数据包，而不是前端静态页面是否存在。现场演示应从“展示站 → 登录 → 项目数据 → 三维场景”顺序录制，并保留服务离线时的降级提示截图。

## 运行时复核补充

本机当前 `127.0.0.1:8090` 没有监听进程，且 `frontend/vendor/` 只有 Leaflet，没有 SuperMap3D 运行库。因此此环境无法显示真实 SCT 地形；页面现在会进入“洛南县离线预览”，而不是因为空场景提前返回。另一个占用 `127.0.0.1:8000` 的服务是“天枢碳眼”应用，不是本项目，本项目验证地址为 `http://127.0.0.1:8010`。

已修复 Windows 损坏 `NETRC` 引发的 GBK 解码异常：iServer 请求默认关闭环境代理/netrc 继承，离线场景接口从 500 改为可识别的 `degraded` 响应。

仍需列入后续 M4 的高风险项：`data/manifest.json` 中洛南边界、乡镇、DEM、约束和 GEE 缓存均为 `missing`；乡镇排序、地块评估和大棚检测仍存在明确的模拟/随机降级路径。比赛演示不得把这些降级结果称为正式评估证据。
